Speed and memory optimization

prusie fits the same model as susieR 0.16.6. The techniques on this page change how the required quantities are computed: which arrays are stored, how many passes are made over the data and in which order floating-point operations are carried out. They do not change the model, priors, stopping rules or the set of variants. Implementation describes the call structure in which they operate; Performance reports measured runtimes and memory.

Principles

  • Mathematical equivalence. Every technique computes the same quantity as the direct formula in exact arithmetic. Some leave the floating-point result bitwise unchanged (for example, removing a repeated pass over the input). Others reassociate sums (for example, grouping exactly equal columns), so results can differ at rounding level.
  • No approximation. There is no LD thresholding, pruning, low-rank approximation or reduced-precision arithmetic. No variant is merged, removed or reordered, and the effects are updated one at a time.
  • Automatic, deterministic dispatch. A fast path is chosen from the input (layout, size, value bounds, exact equality) and the CPU's instruction set. The choice never depends on timers, and there is no environment variable or option that selects an alternative mathematical path. Each fast path checks its preconditions and falls back to the general computation when they fail.
  • Measured acceptance. A change must keep the complete final component alpha matrices within absolute error 1e-5 of pinned susieR 0.16.6 (numerical accuracy). It must also be faster on more than half of a fixed benchmark panel without slowing any predeclared group of cases (data type, variant count or iteration count); see contributing.

Fewer passes over the input matrix

Zero-copy input

A C-contiguous float64 XtX or R is validated in place. Python passes its transpose, a view that is column-major in the same memory, so the solver reads it without copying. Other dtypes or layouts are first converted to a C-ordered float64 array; this is the only copy of an ordinary input.

One validation traversal

Validation needs three properties: every entry is finite, the diagonal is nonnegative and the matrix is exactly symmetric (or must be repaired). One native pass over 32 × 32 tiles checks all three, keeping both sides of each transposed comparison in cache, and creates no p×pp\times pp×p temporary. For z-score RSS input (susie_rss with z-scores, or bhat and shat without var_y, and known nnn), the comparison uses (n−1)Rij(n-1)R_{ij}(n−1)Rij​ and (n−1)Rji(n-1)R_{ji}(n−1)Rji​, the values the model actually uses.

On x86-64, a vectorized proof first tries to accept contiguous LD matrices whose diagonal is within 10−810^{-8}10−8 of one, whose entries do not exceed 1+10−81+10^{-8}1+10−8 in magnitude and which are exactly symmetric. If the proof succeeds, the complete checks are already established; if it fails, the complete checks decide. PRUSIE_NUM_THREADS (default 1, limited to 1–32) sets the number of threads for this proof when p≥1024p\ge1024p≥1024. It is read once per process and does not change any result.

Fused validation and repair

As in susieR's dense path, an exactly asymmetric matrix produces a warning and is replaced by (M+MT)/2(\mathbf M+\mathbf M^T)/2(M+MT)/2, after any factor n−1n-1n−1 is applied. The repair writes both triangles from one computed value into a single new p×pp\times pp×p array, tile by tile, and checks finiteness and the diagonal in the same pass. The result is symmetric by construction, so it is not validated again.

For z-score RSS input supplied as an aligned, C-contiguous float64 array, with z_method given as a string and standard Python warning handling (display, filters, recording or logging capture), validation and repair are fused into one traversal. That traversal computes the averaged matrix while it checks the input, and discards it if the input is exactly symmetric. The warning is still emitted at its usual point, before any repair error. Otherwise validation, the warning and the repair run in that order, so a matrix that needs repair is read twice. Error messages and their priority are the same on both paths. prusie assumes that input arrays are not modified while a call is running; warning callbacks that modify inputs, and replacing warnings.warn before importing prusie, are not supported.

Implicit scaling

The working matrix is Q=a D−1MD−1\mathbf Q=a\,\mathbf D^{-1}\mathbf M\mathbf D^{-1}Q=aD−1MD−1, where M\mathbf MM is the validated matrix and D\mathbf DD holds the predictor scales. Dense matrix–vector kernel

The column-major product Qv\mathbf Q\mathbf vQv adds the columns jjj with vj≠0v_j\ne0vj​=0 in ascending order. Zero coefficients are skipped, so an effect whose prior variance is zero, with mℓ=0\mathbf m_\ell=\mathbf 0mℓ​=0, costs no matrix work. Four nonzero columns are accumulated into each output element while it is held in a register, so the output vector is loaded and stored once per four columns instead of once per column. Each element still receives its additions in ascending column order, with separate float64 multiplies and adds, so this reduces memory traffic without changing the arithmetic of a column-by-column product.

On x86-64 the same kernel is also compiled for AVX2 and chosen at run time when the CPU supports it; other CPUs use the portable build. Component updates are sequential, and each product uses one thread.

Exact signed-column classes

An LD matrix can contain columns that are exactly equal, or exact negatives of one another, for example for variants with identical genotypes in the LD sample. If the ppp columns fall into ggg such classes, a dense product can add the signed coefficients of each class first and multiply only ggg columns.

  • Product. The signed coefficients of each class are added with compensated summation, and M\mathbf MM is multiplied by the ggg class sums placed at representative columns, costing O(pg)O(pg)O(pg) instead of O(p2)O(p^2)O(p2). If every row is also proved to satisfy the same relations, a g×gg\times gg×g matrix of representative entries is stored and the product costs O(g2)O(g^2)O(g2), plus O(p)O(p)O(p) for grouping and expansion.
  • Discovery. Hashes of 16 sampled entries per column, and of complete columns within crowded buckets, only propose candidates. A relation M⋅k=±M⋅j\mathbf M_{\cdot k}=\pm\mathbf M_{\cdot j}M⋅k​=±M⋅j​ is accepted only when all ppp entries compare equal in float64, with no tolerance or rounding. If the proved number of classes ggg exceeds 7p/87p/87p/8, no plan is built and the ordinary kernel is used for the rest of the call.
  • Fallback. A nonfinite class sum, intermediate or result sends that product to the ordinary kernel.

Discovery reads the whole matrix and costs order p2p^2p2 comparisons, so it pays off only when enough products follow. Since the number of remaining sweeps is unknown, prusie decides with a deterministic rent-or-buy rule. A product is dense when its coefficient vector has at least ⌈p/8⌉\lceil p/8\rceil⌈p/8⌉ nonzero entries; sparser products always use the ordinary kernel and are not counted.

  1. At the first dense product, a screen hashes the 16 sampled entries of every column. The number of distinct hashes g^\hat gg^​ is a lower bound on ggg. If g^>7p/8\hat g>7p/8g^​>7p/8, or the matrix is not stored column-contiguously, discovery is abandoned for the rest of the call.
  2. Each ordinary dense product with kkk nonzero coefficients, including the first, adds the work a plan would have saved, max⁡{0,(c1pk+c2p)−(c3g^2+c4p)}\max\{0,(c_1pk+c_2p)-(c_3\hat g^2+c_4p)\}max{0,(c1​pk+c2​p)−(c3​g^​2+c4​p)}, to a running total RRR.
  3. Before a dense product, discovery runs once if R≥c5p2+c6g^2R\ge c_5p^2+c_6\hat g^2R≥c5​p2+c6​g^​2, the estimated cost of discovery and of building the compact matrix.

The weights c1,…,c6c_1,\dots,c_6c1​,…,c6​ are fixed operation-count constants, calibrated on real LD matrices separate from those used to evaluate the rule; they are not timings measured during a call. Their current values in activation.rs are approximately c1=1.453c_1=1.453c1​=1.453, c2=7161c_2=7161c2​=7161, c3=2.226c_3=2.226c3​=2.226, c4=419.8c_4=419.8c4​=419.8, c5=5.058c_5=5.058c5​=5.058 and c6=18.15c_6=18.15c6​=18.15. A fit that stops early never pays for discovery; a long fit buys the plan once the work it would already have saved covers its cost. Discovery runs at most once per native operator, and a failed screen or proof is never retried.

The plan is built for the matrix actually multiplied: M\mathbf MM under implicit scaling, otherwise the materialized Q\mathbf QQ. Posterior coordinates and scaling are unchanged; no variant is merged or removed. Grouping changes only the order of floating-point additions, so exact matrix relations do not imply bitwise equality with a dense product. Refinement can perform several native fits, each with its own operator and discovery decision. The plan saves work, not memory: it adds O(p)O(p)O(p) storage, and g2g^2g2 values for the compact form, while the full matrix is retained. Individual-level designs and the RSS models with a Python sweep loop do not use it.

Grouped sampling variances

The sampling variances are recomputed only when σ2\sigma^2σ2 changes. When they take at most 16 distinct values, the log term and the factor V/{s2(V+s2)}V/\{s^2(V+s^2)\}V/{s2(V+s2)} are computed once per distinct value. z-score RSS input with unit LD diagonal has a single value.

For s2=0.1s^2=0.1s2=0.1, V=0.2V=0.2V=0.2 and marginal estimates (0.1,0.2,0.3)(0.1,0.2,0.3)(0.1,0.2,0.3), the common log term is -0.549306 and the denominator is 0.03. The log Bayes factors are (-0.515973, -0.415973, -0.249306).

Each variant then needs one multiply and one add. Grouping applies to the posterior and, with "optim" or "simple", to every evaluation during the prior-variance search. More than 16 distinct sampling variances, a nonfinite estimate or a nonfinite or subnormal group term fall back to the per-variant formula.

Search invariants

Within one effect update only VVV changes during the search, so 12b^j2\tfrac12\widehat b_j^221​bj2​ is computed once and reused by every evaluation. With equal prior weights, the largest log weight, which the log-sum-exp needs, is taken from per-group maxima of 12b^j2\tfrac12\widehat b_j^221​bj2​ instead of a separate pass over the variants, because each group's factor is nonnegative. At V=0V=0V=0 every Bayes factor is one, so the value is the common log prior weight plus log⁡p\log plogp. These quantities are rebuilt within each fit; nothing is carried between fits.

Vector exponentials

On native GNU/Linux x86-64 builds, the shifted exponentials exp⁡(xj−max⁡kxk)\exp(x_j-\max_k x_k)exp(xj​−maxk​xk​) use the system vector math library (glibc libmvec, four values per AVX2 instruction or two per SSE2 instruction) when it is available. Scalar evaluation handles unavailable symbols, the remaining tail values and nondefault caller floating-point modes (rounding direction, flush-to-zero or denormals-are-zero). Initialization is cached, and the caller's floating-point environment is preserved. With the AVX2 exponential, equal prior weights and at most four sampling-variance groups, the per-variant log weights of the search are also filled four at a time, with separate multiplies and adds. The compile-time portable-math feature removes the vector library path; see numerical reproducibility.

Summation of likelihood weights

The search objective adds ppp nonnegative exponentiated weights. These are added by a balanced pairwise tree, whose rounding error grows with log⁡2p\log_2 plog2​p rather than ppp, and which is cheaper than compensated summation. Because every term is nonnegative there is no cancellation. Signed sums, such as the KL terms and ER2, and the normalization of the posterior weights keep compensated summation.

Individual-level designs

susie never forms the p×pp\times pp×p matrix XTX\mathbf X^T\mathbf XXTX. Each product is evaluated as XT(Xv)\mathbf X^T(\mathbf X\mathbf v)XT(Xv), costing O(np)O(np)O(np) for a dense design and O(nnz)O(\mathrm{nnz})O(nnz) for a sparse one. Centering and scaling are applied as column means and scales inside the product, so the centered design is not stored and sparse input stays sparse. The optional null column is represented virtually. The trend-filtering design X=(−upper-triangular ones)order+1\mathbf X=(-\text{upper-triangular ones})^{\text{order}+1}X=(−upper-triangular ones)order+1 is applied with cumulative sums in O(n)O(n)O(n) storage, without constructing X\mathbf XX. Ordinary single-panel RSS fits with a reference genotype matrix X use the same matrix-free representation.

Memory

At p=5000p=5000p=5000, 8p2=200,000,0008p^2=200,000,0008p2=200,000,000 bytes, or approximately 190.7 MiB.

A dense float64 matrix dominates memory, so prusie avoids further p×pp\times pp×p arrays where it can. An ordinary fit with a C-contiguous float64 matrix, symmetric input and implicit scaling holds only the input matrix at this size; everything else is O(Lp)O(Lp)O(Lp). Additional p×pp\times pp×p arrays are created only:

  • when the input is not C-contiguous float64 (one converted copy);
  • by asymmetry repair (one repaired array), and on the fused path also as a discarded buffer when a symmetric input is not accepted by the fast proof;
  • by materialized scaling, including the rare temporary for an implicit product that overflows;
  • by maf filtering or a null column (null_weight > 0), which build a modified matrix;
  • by RSS routes that construct their own matrix: the bhat/shat/var_y route, finite-reference and mismatch corrections, multiple reference panels and susie_rss_lambda;
  • by retained analysis (retain_data, track_fit, refine or model_init for supported models), which keeps owned read-only copies of the inputs.

Credible-set purity reads only the correlation entries among each candidate set's members. While checking min_abs_corr, it stops at the first pair below the threshold, because that pair already proves rejection; retained sets visit every pair to report the minimum, mean and median.

Threads

The solver uses one thread. Effects are updated sequentially because each update uses the residual left by the previous one (a Gauss–Seidel scheme); updating them in parallel would be a different algorithm. Parallelism comes from vector instructions within a thread. The only native threads are the optional PRUSIE_NUM_THREADS workers of the symmetry proof described above. NumPy operations in Python follow NumPy's own BLAS threading settings.

What prusie does not do

  • It does not reproduce R's accumulation order or use extended precision to imitate R.
  • It does not approximate LD, prune variants, or switch to float32.
  • It does not update effects in parallel or reorder them.
  • It does not offer switches that select alternative mathematical paths.

The reassociations above, together with platform vector math libraries, mean that results can differ from susieR, and between platforms, at rounding level. These differences are assessed with the complete-alpha tolerance, not bitwise equality; see numerical accuracy.
