Numerical accuracy

Numerical comparisons assess how closely prusie's fitted SuSiE posteriors agree with susieR when both implementations receive the same inputs and fitting settings. This page compares prusie 0.3.0 with susieR 0.16.6, using the complete alpha matrix of component inclusion probabilities as the primary comparison.

The evidence includes fixed-reference checks, fresh susieR fits for FinnGen type 2 diabetes GWAS loci and GTEx Whole_Blood eQTL analyses, and an independent toy example. Results apply to the tested configurations; numerical agreement is separate from the statistical calibration of variant inclusion probabilities and credible sets.

Component posterior validation

Comparisons use susieR 0.16.6, commit 8e56a8e038e989856d106d9ca5175cc664fea9d2, with matched inputs, model settings and verified variant order. Each case is summarized by the maximum absolute difference across its complete final alpha matrix, keeping the original component rows and variant columns, including inactive components and components without credible sets. Every entry must be finite and in [0,1][0,1][0,1], and each row must sum to one within 1e-10.

Most per-case maximum differences fall near 10−910^{-9}10−9, far below any probability that matters for interpretation. Iteration counts and convergence status were identical in every case and every timed call, and every credible set contained exactly the same variants in both implementations, so these numerical differences do not affect statistical inference. Marginal posterior inclusion probabilities (PIPs), credible-set memberships, posterior moments, Bayes factors, ELBOs and convergence flags are compared separately. See Computational compatibility for the floating-point assumptions.

The fixed-reference validation covers 184 RSS cases, each tested with n_threads=1, 2, 4 and 8, and with both overwrite_ld=False and overwrite_ld=True. Across all 1,472 case–setting comparisons, the largest absolute alpha difference from the fixed R reference was 9.65×10−89.65\times10^{-8}9.65×10−8. Each setting is fitted twice from independently reloaded inputs, giving 2,944 prusie calls. Repeated calls and the saved same-setting prusie comparison arrays agree bit for bit in alpha. The qualification record lists the settings, errors and identities of these checks.

These fixed-reference checks use refine=False and are separate from the fresh-R real-data comparisons and independent toy example. The results cover the tested inputs, model settings and platforms; refinement and stochastic draws across languages require separate validation.

The primary real-data comparison fits FinnGen R13 type 2 diabetes GWAS loci and GTEx v11 Whole_Blood eQTL analyses on exclusive AMD EPYC 7742 nodes, using the AVX2-capable native build and fresh susieR 0.16.6. The arrays are a by-product of the formal timed calls, with no additional fits. R alpha is saved as binary float64. prusie uses n_threads=1 and refine=False. Both implementations receive matched summary statistics, LD and model settings; see the input provenance and fitting methods.

Iterations and alpha differences

prusie and susieR group floating-point operations differently, and each IBSS sweep reuses the previous sweep's results, so small rounding differences can build up over sweeps. The figure plots each case's maximum absolute alpha difference against its iteration count (the larger of the two backends' medians); cases where neither backend converged within max_iter=100 are marked.

In every case where at least one backend converged, the difference was at most 4.05×10−84.05\times10^{-8}4.05×10−8 for GWAS and 2.55×10−72.55\times10^{-7}2.55×10−7 for eQTL. Differences grow only slightly with sweeps. For eQTL, the median rises from 4.25×10−104.25\times10^{-10}4.25×10−10 in cases with 1–5 sweeps (n=8,886n=8{,}886n=8,886) to 1.75×10−91.75\times10^{-9}1.75×10−9 with 21–50 sweeps (n=181n=181n=181). The correlation between iteration count and log⁡10\log_{10}log10​ of the difference is 0.22 for GWAS and 0.23 for eQTL, so most of the case-to-case spread comes from other properties of each problem, such as how well conditioned the LD matrix is.

Independent toy example

The packaged toy example checks numerical agreement on a single simulated dataset, using a separate susieR reference. Load its summary statistics and LD with prusie.load_example().

The independent 500-variant toy example converged in 3 iterations and returned 2 credible sets. Its maximum absolute PIP difference from the separately generated susieR 0.16.6 reference was 1.66e-10.

The dashed lines mark the simulated nonzero effects. Credible-set memberships also match the R reference for this example. See the toy example tutorial for the simulation method, fitting options and packaged reference, and the vector PDF.

Reproduce the comparisons

The benchmark summary and full per-case records provide numerical errors and convergence diagnostics. The compared arrays come from the last retained call of each case (call seven for the 24 cases run under the earlier seven-call schedule, call three otherwise). Follow the regeneration instructions to rebuild the tables and figures from retained measurements without refitting.

The offline toy checks compare a prusie fit with the packaged R reference. The fresh susieR comparison fits both implementations using matched inputs and settings. Repeating the real-data comparisons requires the separately obtained association summaries and LD, with the same variant order and fitting settings. Preserve the frozen inputs and reference files when running new checks.
