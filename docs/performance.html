Performance

These measurements assess the time and memory required for SuSiE-RSS fine-mapping with prusie 0.3.0 and susieR 0.16.6. The comparison uses fresh fits on FinnGen R13 type 2 diabetes GWAS loci and GTEx v11 Whole_Blood eQTL analyses. Runtime covers the complete fitting call; peak resident set size (RSS) is measured in a separate fresh process for each case and implementation.

Measured prusie 0.3.0 against fresh susieR 0.16.6 fits.

Analysis Cases Timing pairs Total-time speed-up¹ Per-case geometric mean² Peak RSS ratio³
GWAS 200 200 27.7× 35× 3.66×
eQTL 14157 14157 19.1× 22.7× 3.77×

¹ Sum of all seven retained R fit times divided by the corresponding prusie total. ² Geometric mean of within-case median-time ratios. ³ Median paired R/prusie fresh-process peak RSS, including interpreter and inputs. The two speed-up summaries use different weighting.

The primary comparison uses one numerical thread per fit on a concurrently loaded AMD EPYC 9754 host: Linux x86-64, glibc 2.35, CPython 3.12.2, NumPy 1.26.4 and R 4.4.0. The measurement records identify the runtime libraries and measured binary. Results apply to these inputs, settings and hardware.

Reproducibility distinguishes the measured binary from the separately qualified release wheel, which was not timed or memory-profiled. Numerical accuracy reports agreement with susieR under the alpha criterion.

Data

The fixed panel contains 200 FinnGen R13 type 2 diabetes GWAS loci (n = 486,019; 89,727 cases and 396,292 controls) and 14,157 GTEx v11 Whole_Blood genes (n = 800). GWAS is fitted with the frozen Gaussian RSS approximation. All cases remain accounted for, including iteration-limit outputs, empty credible sets, numerical discrepancies and operational failures. Gene windows and study participants overlap; cases are not independent biological replications.

For each case, prusie and susieR use the same aligned summary statistics, variant order and signed LD matrix. LD comes from external 1000 Genomes reference samples: 99 Finnish (FIN) samples for GWAS and 525 European (EUR) samples for eQTL. EUR describes the LD reference; the GTEx association cohort was not restricted to European ancestry for this comparison. See the input sources for study and reference provenance and harmonization details.

The alpha counts use the complete-matrix comparison criterion. The eQTL discrepancy remains included in the descriptive performance summaries; numerical accuracy reports it separately.

Methods

Timing surrounds the public susie_rss call, including input validation, RSS preparation, IBSS, posterior summaries and credible-set construction. Imports, input reads, explicit garbage collection, numerical comparisons and exports are outside the clock. One warm-up precedes seven retained repeats per case and implementation. Each case's backends run sequentially on the same pinned physical core, with their order alternating by the fixed case index. The primary comparison uses n_threads=1 and overwrite_ld=False.

The headline speed-up is the sum of all seven retained susieR times divided by the corresponding prusie total, separately for GWAS and eQTL. The per-case geometric mean summarizes the ratios of median susieR time to median prusie time, giving each case equal weight. The peak-RSS ratio is susieR peak RSS divided by prusie peak RSS within each case; the table reports the median of these paired ratios. These summaries have different weighting.

Memory is measured separately from timing in a new process for each case and implementation. The process fits once and retains the result. Its resident-memory high-water mark includes the interpreter, imports, input loading, preloaded validation reference and fit. It is read immediately after fitting, before numerical comparisons or result serialization, and reported in MiB.

Fits request L=10 components, capped at the variant count, with tol=0.001, max_iter=100, scaled_prior_variance=0.2, estimated prior variance (estimate_prior_method="optim") and fixed residual variance 1 (estimate_residual_variance=False). Both implementations use uniform variant priors, null_weight=0, standardize=True, coverage=0.95 and min_abs_corr=0.5. Credible-set purity uses all pairs of set members, with n_purity set to the case's variant count. Calls use the Wald RSS adjustment, ELBO convergence, check_prior=True and refine=False. With check_input=False, optional eigenvalue and eigenspace diagnostics are skipped; prusie's basic matrix validation remains within the timed call. Iteration counts and convergence are retained in the records.

Independent cases run concurrently on up to 64 physical cores on the shared host, without selecting quiet periods. Host load and repeat variability are recorded. The per-process address-space limit is 16 GiB for prusie and most R fits; R receives 64 GiB for GWAS inputs with at least 9,000 variants. Thread scaling and opt-in LD overwrite are measured in separate series.

Every complete positive timing pair enters the descriptive timing summaries, including iteration-limit fits, empty credible sets and alpha discrepancies. Memory summaries use complete memory pairs; operational failures remain accounted for separately. Agreement with susieR does not establish model validity.

LD overwrite

On the same host with n_threads=1, overwrite_ld=True lowered fresh-process peak RSS in 183 of 200 GWAS cases; 17 had higher peaks and none tied. The median within-case ratio of peak RSS with overwrite_ld=False to peak RSS with overwrite_ld=True was 1.72. These peaks have the full-process scope described in Methods.

This option may consume the caller's LD array even if the call later fails. Reload the original LD before reuse. The LD workspace contract describes supported inputs and ownership.

The measurement summary records aggregate results, protocol and software identities. The compressed per-case records retain individual timing repeats, fresh-process memory measurements, iteration counts, convergence flags, numerical outcomes and host-load summaries. Compact tables cover the primary comparison, thread scaling, LD overwrite and nested locus windows. The separate paired optimization records support Earlier measurements.

These records retain locus and gene identifiers but omit association vectors, LD matrices and individual genotypes. Repeating fits requires the aligned inputs and fitting settings described in Methods and the real-input guide.

From the repository root, redraw the figures and regenerate this page's tables from the retained measurements:

python tools/benchmark/v030.py figures
python tools/generate_results.py --pages docs/performance.md

These commands need no R or association inputs and run no new fits. Add --check to the second command to verify generated text without rewriting it. The reproducibility guide gives dependencies and the full documentation build commands.

Earlier measurements

Separate paired measurements compare the measured 0.3.0 wheel with earlier prusie implementations on fixed real-data panels: 87 primary cases, 80 confirmation cases and 17 cases with large variant counts. These measurements use AMD EPYC 7742 processors on Burgundy and the paired protocol v10.

The cumulative runtime comparison uses one numerical thread and sums the original eight retained complete calls per case, following one warm-up. Across all 184 cases, total historical-baseline time divided by total 0.3.0 time is 1.73; total intermediate-baseline time divided by total 0.3.0 time is 1.06. The figure labels these frozen baselines MAIN and base, respectively.

Memory in this series is post-fit VmHWM minus current VmRSS immediately before fitting. Pre-fit high-water excess is recorded separately. The figure reports the across-case median of within-case median increments, in MiB. This differs from the full-process peak RSS used in the primary comparison.

These are new paired Burgundy measurements. Cumulative totals do not replace the fixed-panel majority, stratified non-regression check and robustness criteria. The v10 runtime count uses the median of paired-round time ratios; the additional case-median count compares the two within-case median times. These can differ. Memory counts compare within-case medians of incremental peaks. W / T / R means lower, equal and higher candidate measurements. A comparison with 16 retained rounds uses the protocol's single quality retry, pooling both complete windows only for comparisons whose first-window decision was unresolved. Other comparisons retain the original eight rounds. Initial decisions remain in the paired measurement records.

Eight of the nine non-diagnostic panel comparisons are ACCEPTED. The large-p default-path comparison with the previously optimized baseline remains UNRESOLVED_QUALITY: no stratified non-regression veto was observed, but resampling agreement for that decision was 0.942, below the required 0.95, after the single permitted quality retry. This result remains an exception to the robustness criterion. The cause of the recorded large-p/high-iteration slowdown relative to that baseline has not been established.

The paired measurement records retain software identities, hardware, individual observations, repeat variability and initial decisions as well as the final comparisons above.
