Performance

These measurements compare the runtime and memory of SuSiE-RSS fine-mapping with prusie 0.3.0 and susieR 0.16.6 on FinnGen R13 type 2 diabetes GWAS loci and GTEx v11 Whole_Blood eQTL analyses. Both programs fit the same inputs with one numerical thread on exclusive AMD EPYC 7742 nodes.

Measured prusie 0.3.0 against susieR 0.16.6 on the same inputs.

Evaluated cases Cases Cumulative runtime ratio Cumulative fitting-stage ratio Median peak-memory ratio
GWAS 200 49.2× 55.4× 5.11×
eQTL 14,157 26.6× 29.8× 4.60×

The cumulative ratios divide the summed susieR time by the summed prusie time over three retained complete calls of every evaluated case, with one numerical thread; the fitting stage excludes input and LD preparation. The memory ratio is the median of paired susieR/prusie ratios of peak backend-process memory. All measurements are from exclusive AMD EPYC 7742 nodes. Ratios for other traits, tissues, region sizes and LD references may differ; see performance.

The protocol records the timing boundaries and software identities; reproducibility identifies the release and its timing-instrumented copy. Numerical accuracy reports agreement with susieR on the complete alpha matrix.

Data

The fixed panel contains 200 FinnGen R13 type 2 diabetes GWAS loci (n = 486,019; 89,727 cases and 396,292 controls) and 14,157 GTEx v11 Whole_Blood genes (n = 800). GWAS is fitted with the Gaussian RSS approximation. Every case is included, including iteration-limit fits and cases with no credible set. Gene windows and study participants overlap, so cases are not independent biological replicates.

Analysis Cases Variants per case Cases where neither program converged
GWAS 200 1,575 to 19,221 0
eQTL 14,157 7 to 6,862 224

For each case, prusie and susieR use the same aligned summary statistics, variant order and signed LD matrix. LD comes from external 1000 Genomes reference samples: 99 Finnish (FIN) samples for GWAS and 525 European (EUR) samples for eQTL. EUR describes the LD reference; the GTEx association cohort was not restricted to European ancestry for this comparison. See the input sources for study and reference provenance and harmonization details.

Numerical accuracy reports the differences between the two programs' results for every case.

Methods

Complete-call timing surrounds the public susie_rss call, including input validation, RSS preparation, IBSS, posterior summaries and credible-set construction. The fitting-stage time is measured inside the same calls and covers solver initialization, IBSS/SER, ELBO and convergence calculations, and final posterior and credible-set construction. Input handling, LD checks, repair and symmetrization still run but are excluded from the fitting stage. Imports, file reads, LD reconstruction, numerical comparisons and exports are outside both clocks.

Each case and backend runs in a fresh process that loads its inputs untimed, then makes one warm-up and three retained calls. The two backends run one after the other on the same pinned core, in a seeded, balanced order. Calls use n_threads=1 and overwrite_ld=False. Twenty-four cases had already completed seven retained calls under an earlier schedule; their first three are used.

Each timing lane uses one physical core in its own L3 cache domain, with the other cores and SMT siblings of that domain idle. Memory is bound to the lane's NUMA node where supported. Admission reserves at most 90% of node memory, using prior peaks as estimates, and allows at most four cases per socket whose LD matrix exceeds 1 GiB. These reservations are planning estimates, not per-process guarantees.

Inputs are staged to node-local storage. Signed LD is computed with single-thread PLINK before each case from the same reference genotypes, variants, variant order and alleles as the prepared inputs. In a 24-case check against the prepared matrices, the largest absolute LD difference was 2.15×10−142.15\times10^{-14}2.15×10−14, with no sign disagreements.

Both metrics use timing-instrumented copies of the release artifacts. On eight qualification cases, the instrumented copies returned bitwise-identical alpha and PIP arrays and the same iteration counts, convergence flags and credible-set counts as the release; timer overhead was not isolated. The measurement archive documents the exact boundaries.

The cumulative ratio divides the sum of all retained susieR times by the sum of all retained prusie times over the evaluated cases. As a per-case summary, each backend's median over its three calls gives a susieR/prusie ratio for every case; tables report the median and interquartile range (IQR) of these ratios. Totals add one median call per case.

Peak memory is the resident-set high-water mark of each backend process, recorded after its final call: VmHWM for R and ru_maxrss for Python. It includes the interpreter, libraries, loaded inputs, the warm-up and the retained calls, so it is not the memory of a single fit. Memory ratios are medians of per-case susieR/prusie peak ratios.

Fits use L=10 components (capped at the variant count), tol=0.001, max_iter=100, scaled_prior_variance=0.2, estimated prior variance (estimate_prior_method="optim") and fixed residual variance 1 (estimate_residual_variance=False). Both programs use uniform variant priors, null_weight=0, standardize=True, coverage=0.95 and min_abs_corr=0.5. Credible-set purity uses all pairs of set members. Calls use the Wald RSS adjustment, ELBO convergence, check_prior=True, check_input=False and refine=False; prusie's basic matrix validation stays inside the timed call.

Every case enters the summaries, including iteration-limit fits and cases with no credible set. Agreement with susieR does not establish model validity.

Thread scaling

This experiment fitted 87 fixed real-data cases with n_threads 1, 2, 4 and 8 on the same exclusive nodes. Each multithreaded call is paired with its one-thread counterpart over eight rounds. The ratio is the median over rounds of the multithreaded time divided by the one-thread time; lower is faster.

Threads Median time / one-thread time Faster / tied / slower, out of 87
2 0.799 87 / 0 / 0
4 0.735 87 / 0 / 0
8 0.783 79 / 0 / 8

Four threads gave the lowest median ratio. Eight threads were slower than four in 52 of 87 cases, and slower than one thread in 8. See Threads for guidance on 2–4 threads and on which work n_threads controls.

LD overwrite

The overwrite_ld=True option lets prusie reuse the caller's LD array as its working matrix. Each of the 200 GWAS loci was fitted once in a fresh process with each setting, on the same nodes and reconstructed LD.

Loci Equal peaks Lower with overwrite Higher with overwrite Largest gap
200 198 0 2 12 KiB

Peak memory did not change. These LD matrices are exactly symmetric, so the default path already reuses an aligned, C-contiguous float64 matrix without a second dense copy. Overwriting can save memory only when the input needs repair or a layout conversion. Final component probabilities were identical between the two settings.

The option may consume the caller's LD array even if the call later fails; reload the original LD before reuse. The LD workspace contract describes supported inputs.

  • Benchmark protocol SHA-256: 3893ec7f92fc042f15eade88a4c27a452835bf3285dfda037d6133c55fc56825 (hash of the protocol file as executed; the published copy was later edited only to remove host names, so its bytes differ)
  • Statistical reference: R 4.4.0; susieR 0.16.6, 8e56a8e038e989856d106d9ca5175cc664fea9d2.

Both runtime metrics use timing-instrumented copies of these release artifacts; the instrumented native binary is not byte-identical to the release wheel. The patch, derived binary hashes and timing boundaries are in the measurement archive.

The benchmark summary and per-case records keep both timing metrics, call timestamps, peak memory, iteration and convergence outcomes and numerical differences. The LD-overwrite records and thread-scaling records hold the two supplementary experiments. The protocol and archive guide document how the measurements were made.

These records keep locus and gene identifiers but omit association statistics, LD matrices and individual genotypes. Repeating the fits requires the aligned inputs and settings described in Methods and the real-input guide.

From the repository root, redraw the figures and regenerate this page's tables from the published records:

python tools/benchmark/v030.py figures
python tools/generate_results.py --pages docs/performance.md

These commands need neither R nor association inputs and run no fits. Add --check to the second command to verify the generated text without rewriting it. The reproducibility guide lists the dependencies and the full documentation build.
