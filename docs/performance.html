Performance

These measurements assess the time and memory required for SuSiE-RSS fine-mapping with prusie 0.3.0 and susieR 0.16.6. The comparison uses fresh fits on FinnGen R13 type 2 diabetes GWAS loci and GTEx v11 Whole_Blood eQTL analyses. Runtime is measured on Burgundy using exclusive AMD EPYC 7742 nodes, with complete-call and fitting-stage times from the same calls. Peak resident set size (RSS) comes from the earlier local AMD EPYC 9754 measurements.

Data

The fixed panel contains 200 FinnGen R13 type 2 diabetes GWAS loci (n = 486,019; 89,727 cases and 396,292 controls) and 14,157 GTEx v11 Whole_Blood genes (n = 800). GWAS is fitted with the frozen Gaussian RSS approximation. All cases remain accounted for, including iteration-limit outputs, empty credible sets, numerical discrepancies and operational failures. Gene windows and study participants overlap; cases are not independent biological replications.

For each case, prusie and susieR use the same aligned summary statistics, variant order and signed LD matrix. LD comes from external 1000 Genomes reference samples: 99 Finnish (FIN) samples for GWAS and 525 European (EUR) samples for eQTL. EUR describes the LD reference; the GTEx association cohort was not restricted to European ancestry for this comparison. See the input sources for study and reference provenance and harmonization details.

The alpha counts use the complete-matrix comparison criterion. Any discrepancy remains included in the descriptive performance summaries; numerical accuracy lists individual exceedances.

Methods

Complete-call timing surrounds the public susie_rss call, including input validation, RSS preparation, IBSS, posterior summaries and credible-set construction. The added fitting-stage metric directly times solver initialization, IBSS/SER, ELBO and convergence calculations, and final posterior/credible-set construction. Full input handling, LD checks, repair and forced symmetrization are excluded from the fitting stage but still run. Imports, file reads, LD reconstruction, explicit garbage collection, numerical comparisons and exports are outside both clocks.

Each case/backend starts in a fresh process, loads inputs untimed, then makes one warmup and three retained calls. The two backends run sequentially on the same lane in a seeded, balanced order. The primary comparison uses n_threads=1 and overwrite_ld=False. The three-repeat protocol follows the 2026-10-28 amendment: 24 cases had already completed seven retained calls; their first three are used, with every original observation preserved.

Nodes are exclusive and use the same CPU model. Each timing lane occupies one physical core in an L3 domain; its other cores and SMT sibling stay idle. One separate L3 domain serves the coordinator. Memory is bound to the lane's NUMA node where supported, with any fallback recorded. Admission reserves at most 90% of node memory using prior measured peaks as planning estimates and allows at most four cases per socket with an LD matrix larger than 1 GiB. These reservations are estimates, not per-process memory guarantees.

Inputs are staged to node-local storage. Signed LD is reconstructed with single-thread PLINK before each case and removed afterwards. The variants, order, alleles, z-scores and genotype/sample source match the local panel; the reconstructed LD need not be bitwise identical. In the 24-case fidelity sample, the maximum absolute LD difference was 2.15×10−142.15\times10^{-14}2.15×10−14, with no sign disagreements. PLINK made 22 previously slightly asymmetric matrices exactly symmetric. This can affect the native validation/allocation path, so changes from local timing cannot be attributed solely to reduced interference.

Both metrics use instrumented copies of the frozen artifacts. Eight-case qualification preserved final alpha/PIP arrays bit for bit and recorded the same iteration, convergence and CS-count outcomes. Instrumented/original median complete-call ratios ranged from 0.805 to 1.026 for prusie and 0.957 to 1.064 for R. These observations include order and binary-layout effects and do not isolate timestamp overhead. Exact boundaries and limitations are documented with the instrumentation.

For each metric, the headline speed-up is the sum of all three retained R times divided by the corresponding prusie total. The sum-of-medians sensitivity divides the sum of within-case R medians by the sum of prusie medians. The geometric mean of within-case median ratios gives each case equal weight. These are separate summaries with different weighting.

The retained memory experiment used a new process per case/backend on the local AMD EPYC 9754. It fitted once and read the resident-memory high-water mark immediately afterwards, before comparisons or serialization. Peaks include the interpreter, imports, input loading, preloaded validation reference and fit. Published memory ratios are medians of within-case R/prusie peak ratios. Current Burgundy process peaks are diagnostics only.

Fits request L=10 components, capped at the variant count, with tol=0.001, max_iter=100, scaled_prior_variance=0.2, estimated prior variance (estimate_prior_method="optim") and fixed residual variance 1 (estimate_residual_variance=False). Both implementations use uniform variant priors, null_weight=0, standardize=True, coverage=0.95 and min_abs_corr=0.5. Credible-set purity uses all pairs of set members, with n_purity set to the case's variant count. Calls use the Wald RSS adjustment, ELBO convergence, check_prior=True and refine=False. With check_input=False, optional eigenvalue and eigenspace diagnostics are skipped; prusie's basic matrix validation remains within the timed call. Iteration counts and convergence are retained in the records.

Every complete positive timing pair enters the descriptive timing summaries, including iteration-limit fits, empty credible sets and alpha discrepancies. Memory summaries use complete memory pairs; operational failures remain accounted for separately. Agreement with susieR does not establish model validity.

LD overwrite

The separate local AMD EPYC 9754 memory experiment used 200 GWAS cases and one numerical thread. With overwrite_ld=True, 173 cases had a material reduction in fresh-process peak RSS; 27 had no material saving. Differences of about 1.1 MiB or less are ties at measurement resolution, rather than evidence of higher peaks. In the 27 cases without material saving, the median peak was about 1.34 times the LD matrix bytes in both modes. The median within-case False/True peak ratio over all 200 cases was 1.72.

For ordinary z/LD/sample-size fits, the default path can reuse an aligned, C-contiguous float64 LD matrix without a second full dense working copy when its native exact-symmetry/correlation checks and implicit-scaling bounds succeed. Repair, layout conversion, stronger input checks, retained analysis state and exceptional scaling can require additional matrix storage. This statement concerns the storage path; peak RSS alone does not identify which branch a particular fit used.

The separate controlled M1 experiment reported a median paired-round runtime ratio of 0.810 for True/False on 87 cases (75 faster, 12 slower). Its acceptance criterion concerned memory; this runtime result is descriptive.

This option may consume the caller's LD array even if the call later fails. Reload the original LD before reuse. The LD workspace contract describes supported inputs and ownership.

Large-p instruction-count follow-up

A separate Burgundy check compared the measured 0.3.0 integration with its previously optimized parent on the same 17 large-p cases. All user-space instruction-count differences were within the predeclared 0.2% bound; the largest was 0.00480%. Two repetitions on two cases gave a maximum difference of 0.00107%. Under that rule, the conclusion is “no code-path difference; attributed to timing noise.” The historical timing-quality result remains recorded as unresolved; this diagnosis does not rewrite its raw measurements.
