Implementation

prusie fits the SuSiE model through input preparation, single-effect updates and posterior summaries. This page traces a fit from the public functions to the returned SusieResult.

The Python package (src/prusie) checks inputs, prepares the model, chooses a fitting route and assembles results. The Rust binding (rust/prusie-python, imported as prusie._native) connects NumPy arrays to native routines and checks native inputs. The solver crate (rust/prusie-core) implements iterative Bayesian stepwise selection (IBSS) without a Python dependency.

The fitting routes include dynamic RSS models whose sweep loop runs in Python using native single-effect regression. Optimization describes the speed and memory methods.

Fitting routes

susie, susie_suff_stat, susie_rss and susie_rss_lambda prepare a _FitRequest through _request._prepare_request. workhorse._fit selects among three numerical routes, checking for dynamic RSS before dense or design fitting. Native entry names below belong to prusie._native.

Dense susie_suff_stat (susie_ss); remaining susie_rss fits with R fit Rust fit_operator, with DenseGram

With susie_rss(X=...), supplying bhat, shat and var_y builds a dense correlation matrix before fitting. This selects the dense route unless a dynamic RSS model is requested. Refinement, continuation and warm starts

For supported models, _prepare_request calls make_prepared when retain_data=True, tracking, refinement or initialization requires a retained context. PreparedData holds read-only input snapshots and a content signature. continue_fit and refine_fit use refinement._run to call _native.fit on these snapshots, then recompute PIPs and credible sets.

Continuation warm-starts from the saved posterior. For each candidate credible set, refinement makes a cold-start fit with that set's prior weights set to zero, then warm-starts a second fit from its posterior with the original weights and initial variances restored. Each round accepts its best candidate only if the last logged ELBO improves by more than RefinementConfig.absolute_tol. Convergence and refinement describes the search controls.

The retained-data path excludes matrix-free designs, dynamic RSS, mixture, NIG and slot priors, convergence_method="pip", L_greedy, and nondefault median_abs_corr or cs_extension_corr. For these fits, plain refine=True uses workhorse._refine_by_refitting to repeat _fit, except that multi-panel RSS rejects refinement. retain_data=True and a RefinementConfig require a supported model.

A warm-start mapping supplied through model_init or its alias s_init needs alpha, mu and mu2; V and sigma2 are optional. initial_options checks the posterior arrays and supplied variant IDs, allele labels, scales and null-column layout. For a native warm start, Rust rebuilds all component matrix products before the first sweep rather than resuming stored products.

function fit_operator(Q, g, s_y, n, options):
    α_ℓj ← 1/p;  μ_ℓj, μ2_ℓj ← 0
    V_ℓ, σ² ← prepared initial variances
    u_ℓ ← 0;  f ← 0
    if warm start:
        load posterior and any supplied variances; rebuild u_ℓ and f
    method ← estimate_prior_method if estimate_prior_variance else "none"
    log_prior_j ← log(π_j + √ε)
    for t = 1, …, max_iter:

            f ← f − u_ℓ;  r ← g − f
            α_ℓ, μ_ℓ, μ2_ℓ, V_ℓ, lbf_variable_ℓ, lbf_ℓ ← single_effect(

            compute KL_ℓ from this SER posterior and its evidence
            u_ℓ ← Q(α_ℓ ⊙ μ_ℓ);  f ← f + u_ℓ

        ER2 ← expected_residual_sum_squares(g, s_y, diag Q, α, μ, μ2, u)
        ELBO ← −(n/2) log(2πσ²) − ER2 / (2σ²) − Σ_ℓ KL_ℓ

        if ELBO is NaN and any of α, μ, μ2, V is nonfinite: error
        decision ← stopping_decision(current sweep, changes, cycles, controls)
        apply alpha-cycle averaging when required; record diagnostics
        if decision ≠ continue: break

            estimate ← ER2 / n;  reject a nonpositive or nonfinite estimate
            σ² ← clamp(estimate, residual lower bound, residual upper bound)
    for ℓ with V_ℓ < prior_tol:
        α_ℓ ← π;  μ_ℓ, μ2_ℓ, lbf_variable_ℓ, lbf_ℓ, KL_ℓ, V_ℓ ← 0
    return posterior, variances, ELBO history, f, diagnostics

If residual-variance estimation is enabled, its update also follows the final allowed sweep when the stopping decision is still continue. Returned sigma2 can therefore differ from the value used for the last ELBO. Final trimming does not recompute the stored ELBO or fitted crossproduct; Results explains these quantities.

Single-effect regression

The Gaussian SER equations give the Bayes factors and posterior moments. Both the prior-variance search and the posterior use the smoothed log_prior prepared above. The sampling variances are cached until σ2\sigma^2σ2 changes. Bayes factors use a variance floor of ε\varepsilonε; posterior moments use the unfloored sampling variances.

function single_effect(r, diag Q, σ², V, log_prior, method):
    b̂_j ← (1/Q_jj) r_j;  s_j² ← σ²/Q_jj
    logBF_j(V) ← Gaussian log BF using max(s_j², ε)
                  (zero if b̂_j or s_j² is nonfinite)
    h(V) ← logsumexp(logBF_j(V) + log_prior_j)
    if method = "optim":
        candidate ← Brent search maximizing h(V) over log V ∈ [−30, 15]
        if h(candidate) ≥ h(V): V ← candidate
    if method ∈ {"optim", "simple"} and h(0) + check_null_threshold ≥ h(V): V ← 0
    lbf_variable_j ← logBF_j(V);  w_j ← lbf_variable_j + log_prior_j
    weights_j ← exp(w_j − max_k w_k);  total ← Σ_j weights_j
    α_j ← weights_j / total;  lbf ← max_j w_j + log(total)
    for each variant j:
        if r_j/Q_jj and s_j² are finite:
            v_j ← V s_j² / (V + s_j²)
            μ_j ← (v_j / s_j²) (r_j/Q_jj);  μ2_j ← v_j + μ_j²
        else: μ_j, μ2_j ← 0
    if method = "EM": V ← Σ_j α_j μ2_j
    reject nonfinite evidence or moments
    return α, μ, μ2, V, lbf_variable, lbf

With method="none", the supplied variance is retained. EM updates the variance after computing the posterior, so the returned evidence refers to the variance used before that update.

Stopping rule

The native solver rejects infinite ELBOs before applying this decision. For a finite posterior state, the remaining logic is:

function stopping_decision(t, ELBO, ΔELBO, Δα, ΔPIP, cycle, controls):
    if ELBO is NaN and criterion = "joint": return numerical_failure
    if t < min_iter: return continue
    fallback ← ELBO is NaN and criterion = "elbo"
    pip_rule ← criterion = "pip" or (fallback and nan_elbo_pip)
    posterior_stable ← Δα < alpha_tol and ΔPIP < pip_tol
    objective_stable ← ELBO is finite and 0 ≤ ΔELBO < tol
    if pip_rule: satisfied ← Δα < tol and ΔPIP < tol
    else if criterion = "alpha_pip" or fallback: satisfied ← posterior_stable
    else if criterion = "joint": satisfied ← objective_stable and posterior_stable
    else: satisfied ← objective_stable
    if satisfied: return converged
    if cycle lag > 1 and (criterion ≠ "elbo" or fallback):
        if pip_rule: return converged
        return cycle_detected
    return continue

ΔELBO\Delta\mathrm{ELBO}ΔELBO is the change from the preceding sweep; Δα\Delta\alphaΔα and ΔPIP\Delta\mathrm{PIP}ΔPIP are the maximum absolute changes in their respective arrays. Cycle detection compares both arrays with earlier states, using tol for the PIP rule and alpha_tol and pip_tol otherwise. The largest lag is cycle_lag (default 5), and successful or cycle stops require min_iter sweeps (default 2). A PIP-rule cycle stop averages alpha over the cycle in the IBSS loop.

Preparation sets the internal nan_elbo_pip flag when no convergence is supplied and the resolved ConvergenceConfig has default values. Other NaN-ELBO fallbacks use the separate alpha and PIP tolerances. With a finite ELBO, the ELBO rule records cycles without stopping. Stopping rules describes PIP history, averaging and model-specific rule selection.

Dynamic RSS uses rss_models.fit_dynamic and also requires the estimated mismatch-bias change to be at most tol before declaring convergence. Its permitted ConvergenceConfig settings are described in the same reference.

Boundaries and exceptions

Input errors stop a call. A completed fit can still return converged=False; its stopping record explains why.

Errors

Shape, range and option-combination checks raise ValueError. The binding also converts Rust solver error messages to ValueError, preserving the message. Explicit Python type checks raise TypeError, for example for invalid standardize, slot_prior or convergence types. The SusieInputs mapping returned by init_only=True accepts "data" and "params"; another key raises KeyError.

Shared preparation and fitting emit RuntimeWarnings and retain their messages in fit.warnings when a result is returned. Ordinary susie_rss adds its collected input warnings to that list. Input warnings emitted directly by susie_rss_lambda are not copied into it.

Input checks

For dense susie_suff_stat and ordinary susie_rss, matrices must have matching dimensions, finite entries and nonnegative diagonals. Ordinary RSS does not separately enforce a unit LD diagonal or entries in [−1,1][-1,1][−1,1]. The caller must supply correctly scaled, signed LD with matching variant order and effect alleles.

For z-score RSS, the exact symmetry check applies after scaling to the working XtX. With bhat, shat, n and var_y, the reconstructed XtX is always averaged with its transpose. The resulting matrix is also checked for finite entries and a nonnegative diagonal. These routes do not clip eigenvalues or repair a matrix to be positive semidefinite.

For individual-level input, X must be finite and infinite y is rejected. Missing y requires na_rm=True, which omits the corresponding rows. Numerical safeguards

Posterior weights are normalized after subtracting the largest log weight. This prevents exponential overflow without changing relative probabilities. For log weights (1000,999)(1000, 999)(1000,999), e1000e^{1000}e1000 overflows in float64, whereas the shifted form does not:

A 60-digit decimal calculation gives 1000.313261687518; the first normalized weight is 0.731058578630.

In ordinary Gaussian SER, finite sampling variances are floored at float64 machine epsilon ε\varepsilonε for log Bayes factors and the prior-variance objective. Posterior moments use the unfloored variances. Prior weighting uses log⁡(πj+ε)\log(\pi_j+\sqrt\varepsilon)log(πj​+ε​), so a supplied zero weight can retain positive posterior probability. A zero working diagonal gives log BF zero and zero conditional moments; its location probability can remain positive. Single-effect regression shows these branches.

Gaussian SER rejects nonfinite evidence or conditional moments. Native IBSS rejects an infinite ELBO. A NaN ELBO also raises an error if the posterior arrays contain nonfinite entries; otherwise the stopping rules below apply. The native residual-variance update rejects a nonpositive or nonfinite estimate before constraining it by residual_variance_lowerbound and residual_variance_upperbound.

With check_prior=True, the native loop checks the component variances after each sweep, using the current residual variance. Zero-diagonal columns are excluded; with no positive diagonal the bound does not reject a variance.

Brent's prior-variance search checks new trial objectives for finiteness and raises an error if its 1000-iteration limit is exhausted. Native slot-activity updates constrain log-odds to [−20,20][-20,20][−20,20]. Kernel eligibility and fallback rules are described in Optimization.

Convergence outcomes

The native IBSS loop reports these fit.convergence outcomes:

stop_reason converged Meaning
criterion_satisfied True The selected rule accepted the fit, including an eligible PIP-rule cycle
iteration_limit False The sweep limit was reached
cycle_detected False An eligible alpha/PIP cycle at lag greater than one under "alpha_pip", "joint" or an ELBO fallback using separate tolerances

An ELBO decrease larger than tol produces a warning and increments the decrease count. The selected stopping rule still decides whether fitting stops. A NaN ELBO with finite posterior arrays under "elbo" invokes a warned alpha/PIP fallback at or after min_iter. With the internal nan_elbo_pip flag, this uses the PIP rule and averages alpha over an accepted cycle. Otherwise it uses the separate alpha_tol and pip_tol, and a longer cycle returns converged=False without averaging. Stopping rule gives the flag selection and decision order. workhorse._fit warns when the solver returns converged=False, including the iteration count and stop reason.

Dynamic RSS has a separate Python loop and reports elbo_tolerance, alpha_pip_fixed_point, alpha_pip_cycle_<lag> or max_iter. Results explains how to read the stopping record and returned posterior.

Trimming and output shapes

Final trimming resets components with Vℓ<prior_tolV_\ell<\mathtt{prior\_tol}Vℓ​<prior_tol: alpha to the normalized prior weights, and V, moments, log Bayes factors and KL terms to zero. Component rows remain in the result. Native IBSS leaves the stored ELBO and XtXr unchanged; dynamic RSS constructs XtXr from the finalized arrays. Results describes these phases.

With a null column, alpha, mu, mu2 and lbf_variable have one more column than pip. During fitting, credible sets containing the null column are rejected. If no credible set qualifies, PIPs are still returned. PIPs use components with Vℓ>prior_tolV_\ell>\mathtt{prior\_tol}Vℓ​>prior_tol; credible sets use the separate fixed cutoff Vℓ>10−9V_\ell>10^{-9}Vℓ​>10−9.

Native threading

n_threads sets a native thread limit for each call, from 1 to 32, with default 1. Public fitting functions use this option independently of PRUSIE_NUM_THREADS. They do not change process-wide Rayon or BLAS settings. NumPy matrix operations, including those in dynamic RSS, follow their own BLAS threading settings.

With n_threads > 1, large dense Gram products use a private Rayon pool to partition output rows. Each row retains its source-column accumulation order; IBSS components are updated sequentially. Pool creation is skipped for one thread or a matrix dimension below 1024. Product dispatch requires at least 1024 output rows and 1,048,576 matrix entries; a compact product formed from exact signed-column classes uses its reduced dimensions for this check. Matrix-free design operators and the dynamic RSS sweep loop are not parallelized by n_threads. The fitting pool is local to the native call and is dropped when that call ends.

For susie_rss with known n and var_y=None, eligible LD inputs can also use parallel preparation for the sufficient exact-symmetry proof and owned validation and repair. This requires n_threads > 1, at least 1024 variants and a plain NumPy array with aligned, C-contiguous, native float64 storage without dtype metadata. Eligibility is checked on normalized preparation inputs, independently of solver and output controls. Array subclasses, including memory-mapped LD, other dtypes and other layouts prepare serially. The requested solver count is retained when preparation is serial. overwrite_ld=True preparation is always serial; its storage contract is described under Optional LD workspace.

Parallel preparation requires the optional GNU/Linux x86-64 native math shim; portable-math builds use serial preparation. Read-only probes check the caller and every worker for nearest rounding, masked exceptions, disabled subnormal flushing (FTZ/DAZ) and the canonical x87 control word. Unsupported or nonstandard controls select serial preparation; the probes do not change them. Sticky exception flags can accrue on different threads, so equality of the complete floating-point environment is not part of the result contract.

Preparation workers read the matrix under a native read borrow and make no Python calls. Owned repair partitions unordered matrix pairs into disjoint jobs; each job writes both orientations into a separate repair array using the same ordered scaled terms and average as serial preparation. The calling thread dispatches warnings and errors: raw validation errors take priority, and a symmetry warning precedes a deferred repair error.

The preparation owner explicitly joins its workers before later NumPy transformations or warning dispatch, including cleanup on exceptions. It stays out of result options and serialization; fitting creates a separate pool when eligible. A construction failure or recoverable task panic selects the complete serial validator after joining any workers and discarding partial output. A worker join failure prevents a successful result. These explicit preparation joins are separate from the fitting pool's ordinary drop lifecycle.

Numerical reproducibility

prusie uses float64 arithmetic. Summation order and math-library implementations can differ from susieR, so results are compared numerically. Core comparisons use pinned susieR 0.16.6 with matched inputs and fitting settings and report the maximum absolute difference over the complete final alpha matrix, in the original component and variant order. PIPs and other summaries are compared separately. Computational compatibility defines the comparison and probability-validity checks.

On native GNU/Linux x86-64 builds, the optional vector-math shim can evaluate SER exponentials through glibc libmvec, using SSE2 or AVX2 according to library and CPU support. Scalar exponentials are used when vector math is unavailable or the caller's rounding or subnormal controls require them. The compile-time portable-math feature disables this shim and uses scalar exponentials without changing model settings. Bitwise equality across implementations or platforms is not promised.

Numerical accuracy reports the tested configurations and results. Agreement on those cases does not establish agreement for every input, model option or platform.

Dense storage and matrix products

A dense float64 matrix for ppp variants occupies 8p28p^28p2 bytes. Input conversion, symmetry repair and materialized scaling can each require additional full matrices.

At p=5000p=5000p=5000, 8p2=200,000,0008p^2=200,000,0008p2=200,000,000 bytes, or approximately 190.7 MiB.

RSS validation preserves the caller's R by default, using owned storage for repair. For supported z-score inputs with R and known n, susie_rss(overwrite_ld=True) can reuse R for repair. Once writes begin, later errors can leave R and its aliases changed, with no rollback. Reload the original LD before reuse, including after a failed call. Optional LD workspace gives the restrictions.

A sufficient exact-symmetry proof can return without writes. Otherwise, a read-only search must find finite original and scaled entries with unequal scaled values before destructive repair starts. With no such pair, owned preparation keeps R unchanged. Repair holds one mutable NumPy borrow under the GIL and loads both original orientations before either store. With s = n - 1, each pair receives (Rij*s + Rji*s)/2 in that operation order, using original entries Rij and Rji. The traversal allocates no full backup or repair array. Consumed R is scaled XtX with global scale 1; unchanged R retains global scale n−1n-1n−1.

The dense operator can apply RSS and predictor scaling without storing the working matrix. Outside the implicit-scaling bounds, it materializes that matrix once. If the ordinary factored product has a nonfinite intermediate or result, it is retried with a temporary materialized matrix.

Each full traversal of R reads 8p28p^28p2 bytes, about as much as one dense product. Dense products

The column-major product kernel skips zero coefficients and adds columns in ascending order, grouping four nonzero columns per output update. On x86-64, runtime CPU detection selects AVX2 when available, with a portable fallback. Both builds perform the same sequence of separate float64 multiplications and additions. Exact signed-column classes can combine coefficients after proving column relations, keeping separate posterior coordinates for every variant. Native threading describes parallel product dispatch and sequential component updates.

Credible-set purity

_native.cs_pairwise_abs reads pair entries of a supplied matrix directly. With min_abs_corr set and median_abs_corr=None, it returns at the first pair below the threshold, before allocating the m(m−1)/2m(m-1)/2m(m−1)/2 pair values of an mmm-member set; the set is recorded with purity_evaluation="threshold_short_circuit". Retained sets receive complete minimum, mean and median purity.

Runtime and memory depend on the input, matrix structure, preparation, iterations and threads. Reducing temporary storage or adding threads need not reduce runtime.
