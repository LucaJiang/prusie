Implementation

Python prepares the model, validates aligned inputs and assembles the result. A thin PyO3 crate checks NumPy metadata and converts options to typed Rust enums. The solver crate has no Python dependency. It performs sequential IBSS, single-effect regression (SER), variance estimation and objective evaluation.

Solver structure

The Cargo workspace contains rust/prusie-core and rust/prusie-python. Within the solver, ibss.rs controls component updates; ser.rs evaluates single-effect posteriors; optimizer.rs implements the one-dimensional prior-variance search; residual.rs computes expected residual sums of squares. operator.rs handles crossproducts and design.rs applies individual-level design matrices. The binding crate owns NumPy borrowing, Python option parsing and result conversion.

Individual-level fits apply dense or sparse design matrices directly, without constructing a predictor-by-predictor Gram matrix. Centering and scaling are represented by column means and scales. Sparse input remains sparse. Ordinary single-panel RSS fits with reference X also use this representation. RSS routes that reconstruct a known response scale from bhat, shat and var_y, apply finite-reference or mismatch corrections, combine reference panels, or use susie_rss_lambda construct dense predictor-by-predictor correlation matrices. Dense sufficient-statistic and LD inputs retain their dense representation.

Posterior weights are normalized after subtracting the largest log weight. This prevents exponential overflow without changing relative probabilities.

A 60-digit decimal calculation gives 1000.313261687518; the first normalized weight is 0.731058578630.

The implementation uses ordinary float64 arithmetic. On native GNU/Linux x86-64 builds, shifted exponentials use the system vector math library when available and supported by the CPU; scalar evaluation handles unavailable symbols, tails and nonstandard caller rounding modes. Initialization is cached, and the caller's floating-point environment is preserved. Existing variances are used directly without log/exp round trips. Complete final component alpha matrices are compared with pinned susieR 0.16.6 at absolute tolerance 1e-5, with original component and variant order retained. PIPs and other summaries are separate diagnostics; see numerical accuracy.

Dense storage and matrix products

At p=5000p=5000p=5000, 8p2=200,000,0008p^2=200,000,0008p2=200,000,000 bytes, or approximately 190.7 MiB.

The dense operator applies diagonal scaling implicitly, avoiding a separate scaled matrix when the factors permit safe evaluation. Its products use a four-column kernel with runtime-checked AVX2 support and a portable fallback. Gaussian single-effect updates reuse groups of equal sampling variance. Default optimizations are selected using numerical validation and lower median complete-call runtime on a strict majority of a fixed case panel; this does not imply every input is faster. There are no environment variables for selecting alternative mathematical paths. PRUSIE_NUM_THREADS controls native matrix-check threads (1–32), is read once per process, and should be set before importing prusie. Component updates are sequential. The primary comparisons use one numerical thread throughout.
