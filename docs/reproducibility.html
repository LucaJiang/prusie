Reproducibility

Reproducing a fine-mapping fit from summary statistics requires the same aligned association summaries, LD matrix, variant order and fitting settings. The real GWAS and eQTL inputs must be obtained separately from their sources.

The repository includes measurement records for regenerating the published benchmark tables and figures, and a packaged toy example that runs offline.

Tables and figures

The published benchmark tables and figures can be regenerated from retained measurements without R or the association inputs. From the repository root, with Node.js available for documentation rendering, run:

python -m pip install -r tools/docs-requirements.txt
python tools/model_examples.py
python tools/benchmark/v030.py figures
python tools/generate_results.py
python tools/build_docs.py

tools/model_examples.py updates the explanatory calculations. The figure command writes SVG and PDF files to docs/assets/benchmark/. tools/generate_results.py updates the generated measurement tables and text. Add --check to tools/model_examples.py or tools/generate_results.py to check its generated Markdown without rewriting it.

The records in docs/assets/benchmark/ have distinct measurement origins:

File Contents
burgundy_summary.json Complete-call and fitting-stage summaries, variant-count quintiles, repeat variability and earlier local comparisons.
burgundy_records.jsonl.gz All 14,363 cases, three retained times per backend/metric, timestamps, outcomes and numerical differences.
burgundy_protocol.json Frozen protocol v2 and artifact hashes.
v030_summary.json and v030_records.jsonl.gz Earlier local EPYC 9754 measurements, retained as the source of published peak RSS. Their old runtime fields are historical.

These records contain case identifiers and measurements; association vectors, LD matrices and individual genotypes are not included. The earlier v030_overwrite.tsv retains the paired local memory results. Historical per-case timing fields are preserved in the compressed archive but do not supply the new runtime figures.

Burgundy protocol

The full panel is 200 GWAS loci, 14,157 eQTL genes and six nested windows of one GWAS locus. Each backend starts a fresh process, loads inputs untimed, makes one warmup and three retained calls, and records both timing metrics from each call. Backends run sequentially on one pinned physical core, with seeded, balanced order. Exclusive nodes use AMD EPYC 7742 processors. One lane per L3 domain leaves the other cores in that domain idle; a separate domain serves the coordinator. NUMA binding, topology, node identity, host samples and per-call timestamps are retained. One numerical thread is enforced in both backends, and the R BLAS probe verifies one thread. The measured nodes were cpunode-011, cpunode-015 and cpunode-029, with 31 timing lanes each. All lane probes used NUMA memory binding. Frequency and governor sysfs readings were unavailable, so no fixed-frequency claim is made.

The signed LD is built on the compute node with PLINK 1.9.0 (27 September 2026), --r square bin, --threads 1, frozen variants/order and counted alleles. The reference has no missing genotypes for the selected samples. The EUR sample list contains one nonfounder; --make-founders includes all 525 selected samples in this calculation. Genotype/reference receipts are verified before staging. The 24-case fidelity sample checks signs and the maximum absolute difference from local LD; its observed maximum is 2.15×10−142.15\times10^{-14}2.15×10−14. This establishes rounding-level agreement on the sample, not bitwise equality or an unmeasured full-panel LD comparison.

Complete-call timing includes validation and preparation. Fitting-stage measurement starts after input/LD preparation and includes initialization, IBSS/SER, convergence/ELBO, and final posterior/credible-set construction. R measures from immediately before susie_workhorse to the final public return. Native timing combines directly measured initialization/solver, output-export and Python-finalization spans. It includes implicit Gram scaling during matrix-vector products; R constructs its scaled Gram matrix in preparation. Minor scalar checks and final-CS submatrix normalization remain in the fitting stage. Small transitions between native spans are omitted. No separately measured cost is subtracted.

The archived harness and instrumentation include exact frozen scripts, patches, hashes and boundary notes. They retain cluster paths and are an execution archive, not a portable cluster installer. The original release artifacts remain unchanged. Eight representative cases were compared against the original artifacts before formal timing; final alpha/PIP arrays were bitwise unchanged, with matching recorded iterations, convergence and CS counts. Complete-call timing shifts are reported in Methods; negligible overhead is not assumed.

Protocol v1 initially retained seven calls. At the repeat-count amendment, 24 completed cases were preserved and contribute their first three retained times. Their saved final alpha/PIP arrays are from retained repeat seven; other cases save retained repeat three. Thirty-one in-flight cases were aborted and restarted under v2 solely because of this amendment. Completed raw outputs and claims were preserved; some unarchived node-local partial outputs from those aborted cases could not be recovered. The archive records that limitation and does not treat those cases as outcome-based reruns.

Only operational failures permit a whole-case retry with identical settings. The 19,221-variant nested window required one retry after R was killed by a NUMA-local out-of-memory event. The failed attempt is preserved; the whole case completed on another node with the same protocol. Node-wide memory admission did not guarantee enough free memory within each NUMA domain. Every fixed case remains in the denominator. The old seven-repeat local statistics and a first-three-retained sensitivity accompany the new repeat variability results. The new process high-water marks are diagnostics; published memory remains the earlier local fresh-process experiment.

Toy example

Use the packaged synthetic toy example to repeat a small fit offline. The wheel includes inputs, metadata, checksums and a separate susieR reference under prusie/data/toy. The toy example tutorial describes the data and analysis.

prusie.load_example() verifies the SHA-256 hashes of inputs.npz and metadata.json, then returns inputs, fitting parameters and generation metadata. Inspect the reference metadata separately:

import json
from importlib.resources import files

resources = files("prusie").joinpath("data/toy")
reference = json.loads(resources.joinpath("reference.json").read_text())
print(reference["susieR_version"], reference["susieR_commit"])

From a checkout with prusie and pytest installed:

python examples/quickstart.py
python -m pytest tests/test_packaged_example.py
python tools/generate_example.py --check

These commands need no R installation.

Regeneration checks

tools/generate_example.py --check regenerates the checkout's arrays in memory and checks their names, shapes, dtypes, finiteness and values. It uses zero relative tolerance and the following absolute tolerances:

Array Absolute tolerance
z-scores (z) 8e-14
LD correlations (R) 5e-15
Marginal effects (bhat) 3e-15
Standard errors (shat) 1e-16

True effects (true_beta) and synthetic coordinates (position) must match exactly. Generation metadata must also match, apart from the running NumPy version. The frozen metadata records NumPy 2.2.6 and is left unchanged.

To regenerate the inputs in a separate directory, run:

python tools/generate_example.py --output-dir new-toy-inputs

New metadata records the NumPy version used. The check compares array content independently of compressed archive encoding. Preserve the original inputs and reference files.

R comparison

For a fresh comparison, install jsonlite and susieR 0.16.6 at the commit recorded in reference.json. Verify both the package version and source commit, then choose a new output directory:

python tools/benchmark/reproduce.py --rscript Rscript \
  --validation-only --output-dir new-reference-comparison

--validation-only fits both implementations on the toy inputs and writes results and numerical comparisons below the new directory. It omits the timing and memory series and requires no BLAS-probe compilation. The comparison applies the complete-alpha validation criterion; PIP and credible-set differences remain diagnostics. The comparison guide describes the output records, timing and memory protocols, and portable input format.

Real GWAS and eQTL inputs

The primary real-data comparison uses the following association summaries on GRCh38. Here nnn is the study sample size, separate from the LD reference sample count.

Association source Analyses Study nnn LD reference samples
FinnGen R13, type 2 diabetes (T2D) 200 loci 486,019 99 Finnish (FIN)
GTEx v11, Whole_Blood 14,157 genes 800 525 European (EUR)

For the binary GWAS, nnn is the total number of cases and controls, and RSS uses a Gaussian approximation. The GTEx inputs use the released all-pairs nominal cis-eQTL associations for each selected gene before variant QC.

LD was computed from the IGSR high-coverage collection, release 20220422_3202_phased_SNV_INDEL_SV, after excluding first- and second-degree relatives using the release-specific sample exclusion list. EUR describes the LD reference; the GTEx association cohort was not restricted to European ancestry. External LD can differ from study LD. Gene windows and study participants overlap, so cases are not independent biological replications.

Preparation retained nonpalindromic SNPs with minor allele frequency at least 0.05 in both study and reference, reference missingness at most 0.02 and reference Hardy–Weinberg mid-p value at least 1e-6, together with sequence, allele and duplicate checks. Signed effect estimates divided by their standard errors were aligned to the reference counted ALT allele to form z. Variant order and alleles describes the alignment required by the fitting API.

To repeat a fit, preserve the source release, genome build, sample selection, variant filters, allele orientation, ordered variant IDs, input hashes and fitting parameters. The portable case format records signed summaries, LD and ordered IDs with explicit fitting settings. Downloaded revisions or newly constructed LD panels define different inputs.
