Convergence and refinement

Read why a fit stopped, give an unfinished fit more iterations when appropriate, then search for a better solution and compare the returned results. A stopping rule describes one IBSS trajectory; refinement explores other starting solutions.

Start with a tracked fit

import prusie
from prusie.plots import plot_convergence, plot_refinement

example = prusie.load_example()
fit = prusie.susie_rss(**example["inputs"], **example["parameters"],
                       track_fit="compact", retain_data=True)
print("Stop:", fit.convergence["stop_reason"], "Iterations:", fit.niter)
convergence_view = plot_convergence(fit, layout="compact")

Expected output:

Stop: criterion_satisfied Iterations: 3

Enable track_fit during fitting to retain iteration history. The compact plot shows logged ELBO, signed ΔELBO, Δalpha and ΔPIP. layout="variance" shows prior and residual variances separately; layout="full" includes all six metrics. retain_data=True preserves validated inputs for continuation and refinement.

Continue first, then consider refinement

Reuse a completed fit. For an iteration-limit exit, an explicit continuation can give the same posterior more sweeps:

fit_for_search = fit
if fit.convergence["stop_reason"] == "iteration_limit":
    fit_for_search = prusie.continue_fit(fit, max_iter=100, track_fit="compact")
print("Ready for search:", fit_for_search.ibss_converged)

This example prints Ready for search: True and reuses fit, because the initial fit already satisfied its rule. A continuation call starts from the supplied posterior, retains the original requested criterion and alpha/PIP, minimum-iteration and cycle controls, and inherits the ELBO tolerance when tol is omitted. Its niter counts the new call's sweeps. An explicit tol or convergence=ConvergenceConfig(...) overrides the corresponding controls. Investigate an objective anomaly or cycle before deciding to continue it.

Now run one refinement search with explicit search settings:

search_config = prusie.RefinementConfig(
    max_rounds=10, absolute_tol=1e-3, relative_tol=None,
    max_iter=100, inner_tol=1e-4, candidate_budget=20,
)
refined = prusie.refine_fit(fit_for_search, search_config)
search = refined.refinement
print("Search:", search["status"])
print("Accepted attempts:", sum(row["accepted"] for row in search["history"]),
      "of", len(search["history"]))

For the packaged example:

Search: no_improvement
Accepted attempts: 0 of 2

Refinement requires a valid baseline with retained inputs, not necessarily a converged inner IBSS fit. It inherits the baseline's requested convergence configuration unless explicitly overridden; search_config.inner_tol separately sets the inner ELBO tolerance. A runtime alpha/PIP fallback after a NaN ELBO is recorded as the effective rule and does not replace the original request for later calls.

Each refinement attempt first excludes one retained credible set by setting its prior weights to zero and fits from a cold start. It then restores the original prior and refits, starting from the excluded-variant solution. The saved search records call these steps A and B, respectively.

Candidates are compared using the last logged ELBO with the original prior, before final component trimming, as in pinned susieR. The recomputed post-trimming objective is retained only as a validity check and diagnostic. A candidate must be valid and finite, but need not have converged internally. It must improve the logged ELBO by more than absolute_tol. An unsuccessful search does not establish global optimality.

Without an explicit RefinementConfig, both APIs forward the original fit's iteration budget and tolerance. An explicitly constructed config is a custom search and may intentionally override these settings; the example above does so. For exact definitions, see the prusie implementation, pinned R search and pinned R objective accessor. The saved worked examples report executed prusie searches with their own source identities and settings; their search outcomes should be read separately from the standard-fit comparison.

Compare before and after

Reuse the refined result and the configuration above; these plotting calls do not repeat the search:

convergence_figure = plot_convergence(fit_for_search, after=refined, layout="compact")
search_figure = plot_refinement(fit_for_search, refined, layout="compact")
print("Same PIPs:", bool((fit_for_search.pip == refined.pip).all()))

This example prints Same PIPs: True; the returned trajectory is labelled After search (unchanged). Before and after have independent iteration axes. The refinement figure compares candidate PIPs, ELBO gains relative to the best fit at the start of each round, and the ELBO of accepted solutions. Full records distinguish failed, unconverged, below-threshold, valid but unselected, and accepted candidates.

The problem example illustrates a different outcome: its initial fit satisfies the stopping rule, yet refinement improves the ELBO by 17.4583. The final logged sweep ELBO precedes finalization; use the finalized ELBO for candidate comparisons.

Convergence diagnostics

fit.convergence contains requested/effective criterion, thresholds, iteration count, stop reason, last distances and recorded events. fit.converged and fit.ibss_converged describe the returned inner IBSS fit, independently of search status.

Evidence Reading question
Logged ELBO and signed ΔELBO Is the recorded objective still improving, flat, decreasing or nonfinite?
Maximum absolute Δalpha Are the component probabilities still moving?
Maximum absolute ΔPIP Is marginal variant inclusion still moving?
Requested/effective criterion Which condition was selected, and did a fallback occur?
Stop reason Was the criterion satisfied, an eligible cycle stop taken, the iteration cap reached, or a numerical failure detected?

For biological variant jjj, marginal PIP combines active components:

PIPj=1−∏l:Vl>prior_tol(1−αlj). \mathrm{PIP}_j = 1-\prod_{l:V_l>\mathrm{prior\_tol}}(1-\alpha_{lj}). PIPj​=1−l:Vl​>prior_tol∏​(1−αlj​).

The null column is excluded. Component allocations can move while marginal PIPs stay similar. Exact distances compare consecutive complete IBSS sweeps:

Δα=max⁡l,j∣αlj(t)−αlj(t−1)∣,ΔPIP=max⁡j∣PIPj(t)−PIPj(t−1)∣. \Delta_\alpha=\max_{l,j}|\alpha^{(t)}_{lj}-\alpha^{(t-1)}_{lj}|,\qquad \Delta_{\mathrm{PIP}}=\max_j|\mathrm{PIP}^{(t)}_j-\mathrm{PIP}^{(t-1)}_j|. Δα​=l,jmax​∣αlj(t)​−αlj(t−1)​∣,ΔPIP​=jmax​∣PIPj(t)​−PIPj(t−1)​∣.

The first recorded sweep has no preceding sweep, so its distances are unavailable. Each PIP uses that iteration's component activity. Alpha distance includes any null column; PIP distance does not.

The default finite-ELBO rule, starting at iteration two, is 0≤ΔELBO<tol0\leq\Delta\mathrm{ELBO}<\mathrm{tol}0≤ΔELBO<tol. A negative increment does not satisfy it. The alpha_pip rule requires both probability distances below their separate absolute tolerances; joint requires those conditions and the finite-ELBO rule. min_iter=2 is the default; a larger value delays successful convergence and any cycle stop until that sweep. Repetition of alpha/PIP at lags two through five is diagnostic only for a finite objective in elbo mode. It cannot stop that fit or override an already satisfied convergence criterion. Select a different requested rule explicitly when fitting or continuing:

rule = prusie.ConvergenceConfig(criterion="joint", alpha_tol=1e-6,
                                 pip_tol=1e-6, min_iter=2, cycle_lag=5)

Pass convergence=rule to the desired operation; merely creating this object leaves the completed example unchanged. Plot legends distinguish selected stopping thresholds from diagnostic-only thresholds. Relative ELBO change is reported separately and is not the default stopping condition.

Objective state Behavior
First finite ELBO, following the initial −∞ sentinel No convergence check or fallback; a preceding completed sweep is required
Finite ELBO with a negative or nonfinite increment Does not satisfy the ELBO condition; no alpha/PIP fallback
NaN ELBO in elbo mode At or after min_iter, use the labelled alpha_pip_nonfinite_fallback rule; success requires both posterior distances
NaN ELBO in alpha_pip mode Use the explicitly requested posterior rule and record the nonfinite objective
NaN ELBO in joint mode Stop with numerical_failure and converged=False, even before min_iter
Infinite computed ELBO in any mode Raise ValueError, as in the pinned R fitter

A nonfinite objective cannot win refinement selection. criterion_satisfied means the effective rule succeeded; inspect that rule and objective validity before interpreting the fit. If no stopping condition holds at max_iter, the reason is iteration_limit and converged=False.

Technical details

Iteration phases, finalization and objective conventions

Metrics are recorded after each complete sequential sweep, before any residual variance update. Posterior-mean distance uses bˉj=∑lαljμlj\bar b_j=\sum_l\alpha_{lj}\mu_{lj}bˉj​=∑l​αlj​μlj​ on the working predictor scale. Signed variance changes, top variants, entropy, activity and events accompany the metrics. Online component entropy includes null; posterior resolution instead normalizes biological alpha and reports null mass separately. Relative ELBO change is ΔELBO/max⁡(1,∣ELBOt−1∣)\Delta\mathrm{ELBO}/\max(1,|\mathrm{ELBO}_{t-1}|)ΔELBO/max(1,∣ELBOt−1​∣).

After a non-stopping sweep, residual variance may be updated. Final trimming zeros components with Vl<prior_tolV_l<\mathrm{prior\_tol}Vl​<prior_tol, including at the iteration limit. Stored elbo and XtXr retain their pre-finalization values; evaluate_objective(fit) explicitly recomputes likelihood, KL and fitted products from the complete saved state. convergence['finalization'] separates trim changes from iterations. The CS activity threshold remains 10−910^{-9}10−9; a custom PIP prior_tol can therefore produce different boundary activity.

Ordinary SER uses log(pi + sqrt(eps)); trimmed V=0 components contribute zero KL. This convention and the recorded phase explain small logged-versus-final objective differences. Stage A's hard-exclusion weights remain exactly zero; B restores the original ordinary-prior convention.

Warm-start validation and legacy configuration recovery

Tracking, initialization, refinement or retain_data=True retains validated input snapshots and scale metadata. Their content signature is computed once and reused by continue_fit and refine_fit. Ordinary unretained fits have data_signature=None; missing signatures never establish matching inputs. Set retain_data=True before later continuation. New fits using s_init do not require an input signature. Caller-array changes cannot alter retained inputs.

continue_fit reuses the retained context and starts from the saved posterior. save_analysis preserves an available signature, but excludes the private snapshot. To warm-start a restored retained-origin result, pass the original inputs and s_init=restored to the fitting interface; new inputs are fully validated. A restored ordinary result can initialize a new fit, but cannot continue without the original private retained context.

Supplied variant IDs/order, allele labels, null layout and working scales must agree. An explicit working-coordinate mapping needs alpha, mu, mu2; identity metadata is optional but checked when provided. Optional V and sigma2 are checked; supplied V initializes even fixed-prior fits, while sigma2 is resumed only when residual variance is estimated, as in R. Growing L prioritizes credible-set components and adds uniform, zero-mean rows; requesting fewer effects than the state retains its existing effect count. Fitted crossproducts are rebuilt from the current posterior and inputs; old KL, BF and fitted caches are not reused as current values.

Requested controls are read from params['convergence'], with labelled recovery from diagnostics or retained options for older results. If no original controls were recorded, compatibility defaults are identified rather than presented as inheritance. Per-stage solver_settings and convergence record the resolved controls for refinement runs; older saved files may lack these fields.

Tracking detail, cycle detection and refinement budgets

Compact tracking (True or 'compact') records exact online distances and component summaries. Its alpha display retains rows with maximum alpha at least 2/p2/p2/p and entries at least 1/p1/p1/p, where ppp includes any internal null column. Thresholds, omitted mass and lossy=True are recorded. This display cannot reconstruct the posterior. 'dense' also records full alpha and moments and is intended for small debugging inputs.

A lag-one fixed point is distinct from a short cycle. cycle_lag=5 retains the default diagnostic history in every mode; cycle_lag=1 disables lag-greater-than-one detection. Lagged repetition is recorded independently of the stopping decision. In explicit alpha_pip or joint mode, or the NaN-ELBO fallback, an eligible lag-two-through-five cycle stops only when the requested success criterion has not already held and min_iter has been reached. Such an exit reports cycle_detected and leaves IBSS convergence false. Finite-ELBO mode continues. Every mode retains the complete current posterior; components are not averaged. track_fit=False, 'compact' and 'dense' change recorded history, not fitted values or stopping decisions.

Every search round freezes an incumbent and its CS list. Stage A zeros excluded variant weights and normalizes the remaining full prior, including null. Stage B transfers alpha/mu/mu2, then resets V and sigma2 to the original model initialization. Candidates share immutable inputs and own their posterior arrays. A failed final attempt does not replace an earlier accepted best.

The default absolute improvement threshold avoids accepting numerical noise. The optional relative threshold is disabled by default; after an accepted gain, it can stop further rounds when the gain divided by max⁡(1,∣incumbent objective∣)\max(1,|\mathrm{incumbent\ objective}|)max(1,∣incumbent objective∣) is below the requested value. A candidate budget counts exclusion attempts, each using at most two fits. Round or candidate limits report budget_exhausted. No CS, no improvement, unsupported baseline, all candidates failed and exhausted budgets remain separate outcomes from IBSS stopping.
